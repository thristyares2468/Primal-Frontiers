# Native automation selection contract — M12 tooling

October10,2026. During knowledge request verification a nonexistent PF.Progression.Transactions selector silently ran only the other two tests. The correctly named Records/Component/KnowledgeRequests gate was replayed and passed3/3, but the runner's old count/severity verdict could accept such an incomplete selection.

Scripts/RunNativeAutomation.ps1 now requires every plus-separated Run selector to match at least one exact test or namespace child. Matching is case-insensitive with a dot boundary: PF.Progression matches PF.Progression.Component, while PF.Progression.Knowledge does not match KnowledgeRequests. Returned tests outside all selectors cause refusal. Existing process exit, nonempty report, unique identifiers, counts, success, errors/warnings and fatal/ensure checks remain required. Verdict exposes SelectionChecked, ExpectedFilter, MissingSelectors and UnexpectedTests. Optional Inspect -ExpectedFilter provides the same read-only selection check; legacy callers without a recorded filter remain compatible, explicitly SelectionChecked=false, and must still enforce their own exact fixture contract.

This verifies selector coverage, not a registry snapshot of every test under a broad namespace. Use exact individual names for fixed-count acceptance. No generated reports, gameplay, assets, preferences or save schemas changed; no new C++ build is required for this PowerShell-only change. Current prerequisite Editor14.96s/Game25.27s builds passed in KNOWLEDGE_REQUESTS_M12.md.
