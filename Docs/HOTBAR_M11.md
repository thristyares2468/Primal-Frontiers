## Controls and behavior

Eight bottom-center pictured shortcuts refer to exact owned inventory batch GUIDs. At the existing open-world starting camp, collect real resources with E, press Tab, select a stack, press1–8 to pin it, then Tab to return. During gameplay1–8 selects a shortcut, Q consumes one edible/drink item through the existing server RPC. Controller D-left/right cycles shortcuts; D-down uses one during normal gameplay. Inventory/crafting/building D-pad routes remain contextual. Inventory0 clears the last selected/assigned shortcut, without deleting an item. No items are granted by the UI.

Assignment is local; it does not move/copy/split inventory. Sort/reordering does not change the referenced batch. Expired/removed batches show `lost` and refuse use; another batch of the same type is never substituted. Pin that new batch explicitly. Duplicate pinning moves the shortcut instead of creating another copy. Quantities display the actual current owned replicated batch. Food expiry/nutrition remain unchanged. Dead/missing pawn, Pause, inventory/upgrades, crafting, storage and placement block gameplay shortcut actions. Existing server validates GUID ownership, life, freshness, action quantity and rate limit. No item-grant RPC or client equipment authority.

Current tool/weapon/protection benefits are automatically derived from carried inventory. Hotbar selection is not an equipment change; Q explains nonconsumable items, E gathers and mouse attacks as before. Crafting1–3 retain existing recipe actions while crafting is open. Shortcuts survive respawn with the same controller but reset when changing worlds/recreating the controller; they are not part of persistent world saves. Drag-and-drop, rebinding, equipment slots and physical-controller verification are separate future work.
