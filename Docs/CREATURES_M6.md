# Milestone 6 greybox creatures

September 30 build follow-up: committing M6 changed Unreal's adaptive unity grouping and exposed a native C++ symbol collision between creature and survivor `TAG_PF_Dead`. Renamed only the creature symbol to `TAG_PF_CreatureDead`; the registered gameplay tag and behavior are unchanged. Editor rebuilt in 14.10 s and `M7ClockCore/index.json` passed four tests, including `PF.Creatures.Lifecycle` and `PF.Survival.Component` (plus the new clock and existing command arguments), zero failures/warnings. This supersedes the pre-commit build result for that build-layout issue.

Gate passed for the bounded scenario; see `MILESTONES.md` for exact evidence and the slowed manual kill replay condition. Two original data definitions, `Creature_Forager` and `Creature_Prowler`, use existing engine spheres and text labels. No acquired or generated art. The user has their own assets available: notify them before any future art-integration stage, and agree the assets to integrate first. M6-M8 remain greybox.

Authority runs a bounded 10 Hz creature decision loop. It selects the nearest living survivor in range with unobstructed line of sight; passive foragers flee and hostile prowlers chase. Movement uses the engine AIController and navigation mesh, not teleportation. Idle alternates with four deterministic patrol destinations. Prowlers have a 15 m home leash, a visible 0.6 s attack state and a 1.2 s cooldown; damage rechecks range, sight and life state when the windup finishes. Full AI runs only on the server; movement, health, target and Gameplay Tag state replicate.

Click outside inventory/crafting/building mode attacks the server-derived 2.5 m view target, costs five stamina and has a 0.5 s server cooldown. Bare hands deal 20 damage; carrying the M4 tool deals 35. Clients cannot specify target, damage or reach. The creature damage API rejects client-side, nonfinite, negative and repeated death damage. Death disables collision/movement, creates exactly one perishable food pickup and removes the corpse after 12 seconds. Loot reuses the existing catalog, inventory, pickup and expiry contracts.

Each spawn point keeps one resident, waits 30 seconds after its last living observation and retries only at bounded intervals. A world-wide eight-creature cap includes corpses, bounding both AI and replication. Spawning validates catalog, navigation projection, capsule clearance and the development world envelope. `PF.SpawnCreature CreatureId` is an authoritative developer command with the same checks; it requires exactly one possessed player. `PF.ResetCreatures` is restricted to standalone `L_M6Creatures`, pauses its spawners and clears only creature actors without loot or saving the map. `PF.TestCreatureAI` checks runtime integrity; it does not substitute for the live navigation test.

The small M6 map extends the existing greybox test area with primitive ground, a pathfinding obstacle, two spawn points and bounded baked navigation. `NavigationSystem` is an additional built-in module dependency; no external plugin. `PFNavigationBounds::BuildNavigation` permits editor-only setup and waits for supported navigation generation completion. Dynamic construction remains a physical blocker; advanced dynamically rebuilt navigation and complex multi-floor creature traversal are outside this slice.
