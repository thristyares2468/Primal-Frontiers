## Implemented behavior

- A replicated native `APFCraftingStation` uses original engine cubes and text labels. Public workbench:125% crafting speed for Tool, Material, Weapon and Protection. Public refinery:150% for the five existing Copper/Iron/Gold/Silver/Titanium refinement recipes. Food receives no station bonus.
- Server chooses the highest eligible bonus without stacking stations. The current pawn must be alive/owned, in the same world, within2.5m, with clear Visibility line of sight. Invalid tags/range/multipliers fail closed. The client never supplies a multiplier or station identity.
- Existing portable recipes remain available. Recipe duration is divided by the station multiplier and the existing separately earned crafting-speed multiplier; both are snapshotted at start. Owner-only replicated job fields report the server's actual station. The nearby recipe preview is informational.
- A boosted job rechecks the same station before completion. Leaving range, obstruction, destroying the station or changing its configuration cancels before conversion. Inputs are kept; unchanged exact-batch transaction checks still prevent duplicate/expired/missing ingredient conversion. Cancelled work gives no XP or output.
- These are public, stateless fixtures: no player placement, ownership, fuel inventory, station storage, unattended queue or powered manufacture is claimed. Their static authored presence survives ordinary world load, without new save records/schema or changing resource identities. Player-built stations remain a separate future task.
- Dedicated servers never dereference the presentation TextRender component stripped from loaded maps. The first server run exposed that crash; the guard is a production correction, not an engine/RHI workaround.
